Judging (what actually decides the money)

Stage 1 — Pass/Fail

  • Project fits the chosen track's theme.
  • Required tech is used at runtime — an import, entry point, loaded MCP/agent config — not just named in the README.
  • Fire TV exception: any framework is fine, but the demo video must show it running on Fire OS/Vega (device or simulator).
  • Amazon's internal review team reads your friction logs here and may forward up to 10% to Stage 2.

Stage 2 — Four equal weights

  • Tech Implementation — effective use of required APIs/SDKs/device capabilities (tie-breaker #1).
  • Design — coherent, intuitive product experience for that device (D-pad focus on TV, voice flow on Alexa+).
  • Potential Impact — credible, specific customer need; an audience beyond the hackathon.
  • Quality of the Idea — creative use of the tools; understanding of ecosystem + end users.

2. Track Deep Dives

What each track's tooling actually is in Sept 2026, what judges verify, and where the open space is. This is the distilled output of 6 dedicated track-research agents.

Track 1 · Fire TV

Vega OS is the future — and the gap

  • Two incompatible targets: Fire OS 16 (Android/API 28, ADB sideload) vs Vega OS (Amazon's Linux/RN OS on Fire TV Stick 4K Select + Stick HD). Apps don't cross over. No new Fire TV models ship Fire OS — a Vega-native build signals ecosystem alignment.
  • Tooling: Vega Developer Tools (CLI + Vega Studio + Vega Virtual Device simulator, Mac/Linux) · Amazon Devices Builder Tools — an MCP server + Agent Skills that teach your AI agent Fire TV patterns (npx -y @amazon-devices/amazon-devices-buildertools-mcp@latest --init-context) · starters: react-native-multi-tv-app-sample (one codebase → Vega/Android TV/web), vega-sports-app, vega-video-sample.
  • Media: ExoPlayer/Widevine on Fire OS, Shaka Player on web, @amzn/react-native-w3cmedia on Vega. VSK for Fire TV is deprecated — multimodal now via Media Session API + deep-link intents.
  • CV on TV: Fire TV Cube supports USB UVC webcams (Camera2 + TFLite/ML Kit). Sticks lack full USB; Vega camera support unverified — the riskiest priority category.
  • Open space: Vega has no DVR/Jellyfin, few utilities, zero native games, no local-media players. Fire App Builder is end-of-support.

Verify: video on device/simulator · judges explicitly score "basic streaming UI / simple video player / remote game" as obvious.

Track 2 · Alexa+

MCP is the open door — partner tools are gated

  • Pin spec 2025-11-25 + Streamable HTTP. The 2026-07-28 release made MCP stateless (removed initialize, Mcp-Session-Id, GET SSE stream) — an Alexa+ client won't handshake with a 2026-only server. Devpost allows "later, once confirmed" — don't gamble.
  • Self-hosted = your server on a remote HTTPS URL; Alexa+ acts as MCP client. Production onboarding wants OAuth 2.1 + PKCE (S256), RFC 9728 protected-resource metadata, well-known AS metadata. For the hackathon: skip auth (no-auth/bearer on localhost or tunnel) — the FAQ says participants can't access partner tooling, so no public integration is required.
  • Three valid paths: ① self-hosted MCP server ② Agent Skill ③ simulated Alexa+ web app (no framework required — but repo must include the simulation source and the demo must show it working).
  • Saturated: travel/hotels, restaurants, rides, tickets, big smart-home brands, Canva, Yelp. Fresh: MCP Apps interactive resourceUri visuals (few will use it), caretaking, accessibility, education, local niche services, elicitations, DX.
  • Weekend build: TS SDK @modelcontextprotocol/sdk 1.30.x → McpServer + zod schemas + StreamableHTTPServerTransport → verify in MCP Inspector → cloudflared tunnel → agent loop (Claude/OpenAI tool-calling) + chat/card UI.

Verify: runtime tool calls visible (MCP Inspector B-roll works great), simulation source in repo.

Track 3 · Bee

Live data or disqualification

  • What Bee is: $49.99 band/clip (US) + free iPhone/Android/Apple Watch app. Transcribes conversations, discards audio after processing — only transcripts/summaries persist. Derived data: transcripts w/ speaker IDs, daily summaries, facts (personal memory), todos, voice notes, insights, location clusters.
  • Dev surface: CLI (npm i -g @beeai/cli: bee today/facts/todos/search/conversations/daily/insights, bee sync, bee changed --cursor) · MCP server (~39 tools: bee_search, transcripts, facts/todos CRUD) · Agent Skill (npx skills add bee-computer/bee-skill) · local proxy bee proxy → http://127.0.0.1:8787/v1/* with SSE stream. Developer Mode = tap app version ×5 in iOS settings.
  • Device-free path: a free Apple Watch running Bee software is explicitly allowed. Android Developer Mode requires a paired Bee device. There is no official simulator — use mocks for dev, real data on camera for the video.
  • Rules: "mentioning Bee without demonstrating live data does not count." Show bee stream / proxy SSE live.
  • Creative list: cross-device orchestration (Bee + Alexa + Fire TV), facts/insight depth, realtime, self-improvement. Obvious: notification relay / logging.

Hedge: verify you (or a teammate) have an Apple Watch on iOS before committing to this track.

Track 4 · Ring

Hardware-free since May 2026 — but no actuators

  • Ring Developer Portal is GA (Mar 2026). Partner API at api.amazonvision.com (OAuth via oauth.ring.com, Bearer ~4h, 100 TPS, JSON:API) — server-to-server only (CORS blocks browsers). No official SDK — plain HTTP + the ring-api-helloworld Next.js starter.
  • Developers Playground (May 2026): 30-min one-click token, synthetic devices, event simulation (Package/Vehicle/Motion, button_press), full WebRTC/WHEP live view — no account linking, no Ring subscription, no hardware. Plus a Sandbox for unlimited synthetic testing.
  • API surface: GET /v1/devices, history/events, HMAC-signed webhooks (motion_detected human/animal/vehicle, button_press, lifecycle), WHEP streaming, snapshots, MP4 clips. Only write endpoint = Chime audio playback. No official lock/unlock, light, or alarm-arm.
  • Trap: unofficial ring-client-api is not in Ring docs → Stage-1 risk. Marketing copy "access controls" means data/entitlement access, not lock control.
  • Gotchas: media carries a server-side watermark (Aug 2026) — relevant to CV; streams cap 30s (battery)/60s (wired); webhooks need a public HTTPS endpoint (or use Playground sim events).

Verify: "imported and actually called" in code + video showing simulator or device.

Mini challenges — cheap multipliers

AWS Builder

Fastest credible path: API Gateway → Lambda → Strands Agent() on Bedrock (Nova Lite/Micro) + @tool calling DynamoDB/S3; Cognito auth; CDK/Terraform IaC. Or deploy the whole agent to AgentCore Runtime via bedrock-agentcore-starter-toolkit (2 commands).

  • AgentCore = Runtime (agent hosting) · Identity (free via Runtime) · Gateway (Lambda→MCP tools) · Memory · Observability/Evaluations. Use Runtime+Identity+Observability for a "production agent" story.
  • Strands SDK (Python + TypeScript): model-driven loop, @tool decorator, MCP/A2A, swarms, tracing — beats raw Converse API when you need orchestration.
  • Kiro Crew qualifies on its own (rules §4) — no runtime AWS service needed; describe usage in product feedback.
  • Credits: $150/person via form (due Oct 21 noon PT); new accounts get up to $200 for 6 months. Bedrock: use Nova Micro/Lite + Flex tier (−50%) + budget alerts.
  • Documentation bar: product feedback naming services · README "AWS Integration" table (service → purpose → file:line) · Mermaid architecture diagram · IaC in repo · teardown steps.
Open Source

A meaningful PR beats a brand-new repo — borrowing credibility judges already know. Best hybrid: a feature PR with tests plus a small new tool if time allows. The rules' own "creative" example is essentially extending Amazon's react-native-multi-tv-app-sample with Vega support.

  • Target repos: modelcontextprotocol/servers (~90k★, ecosystem-central) · strands-agents/samples (~21 open issues, responsive maintainers, named in AWS Builder) · AmazonAppDev samples · MCP TS/Python SDKs.
  • Licenses: new agent/SDK-ish project → Apache-2.0 (patent grant, matches AWS ecosystem); small tool → MIT. For PRs, upstream's license governs — never add your own.
  • Hygiene: license detectable in the repo About section (add at creation), README with install/run, CONTRIBUTING, tests/CI.
  • Time budget: recon 2–6h · feature PR w/ tests 8–14h · docs-only 1–3h (eligible but scored "obvious") · weekend plan: Sat claim issue → Sun PR + friction log.

🗣️ Language — the multiplier

  • Bhashini (govt): 36 text / 23 voice languages, 24M inferences/day — good integration surface. Sarvam-Translate weaker for Bodo/Dogri/Kashmiri/Manipuri/Santali/Sindhi.

Rule of thumb: any concept that ships in Hindi + 2 regional languages materially scores higher on Potential Impact in India.

What winners actually look like

  • The rules literally name the winners. Each track publishes an "obvious vs creative" list — pick a listed creative bullet and prove it on video.
  • Recent Amazon winners are narrow and practical, not flashy (Amazon Nova 2026: a screen-aware voice agent, a dementia assistant; AWS Lambda 2025: one problem, one sentence, working pipeline).
  • Balance beats depth — the biggest score-killer is over-indexing on one criterion (Devpost judge guidance).
  • First 30s = baseline score: elevator pitch in the opening seconds, finished-looking home screen, one wow moment early, no scaffolding visible.
  • Video is the whole judgment — judges may never run your code. Text + images + video are all they see.

Friction-log blueprint (up to +10%)

Required fields per entry: task attempted → steps taken → expected vs actual → severity → workaround → actionable suggestion. Log as-you-go in FRICTION_LOG.md within 60 min of friction; 6–12 entries; exact command, verbatim error, docs URL + date, environment, time lost.

Strong: "Followed Ring Get Started §3 → redirect loop, 401 on callback; docs reference deprecated client_id. Severity High. Workaround: minted token via API explorer. Suggestion: update §3 param names + error table."
Weak: "Docs were confusing." (No repro, no fix.)

Mechanics: Amazon's internal review team scores logs at Stage 1 and forwards up to 10% to the Stage 2 panel — it's a multiplier on viability, not a rescue.
